# 画像问卷（yammory-survey）

把用户口头讲的自己，变成 yammory_system 里可注入的画像：**七面条目（`memory` 工具）＋ 分领域知识水平（`memory_profile` 工具）**。

## 定位：它是一根针 🪡

**大头留给观察，问卷只做补充。** 后台观察从日常行为里织出画像的布面；问卷只在观察够不着的地方点一下。

问卷只问三类东西：

| 只问 | 例子 |
|---|---|
| 观察**够不着**的 | 意愿、偏好、想做什么（心里的事，行为推不出来） |
| 观察**很久才敢确认**的 | 你在某个领域的真实水平 |
| 观察**看走眼、需校正**的 | 行为给的印象与你的自陈对不上时 |

**预算纪律**：问卷产的条目，长期占比不宜超过约三分之一；某个面若观察已能覆盖，问卷就不去碰。它不该长成一场大调查。

## 何时启动

**只由用户主动发起。** 触发不必卡死句式，用户提到下面这类意思即可：

- 记忆 / 画像 / 问卷：「更新一下我的画像」「你记得我什么」「做次问卷」
- 「问我几个问题」「把我记住」「补一下我的画像」
- 「yammory survey」

不启动的情形：用户只是在聊天里提到自己；用户没要求而你「觉得该多了解他一点」；用户在做别的事。**模型不得自作主张开问卷**——用户没答完的问卷比没有更糟，它留下半张脏画像。

用户中途喊停（「先到这」「够了」），立刻停，把已答的写进去，别追问。

## 一轮的形状

```
读画像 → 挑板块（用户指定 > 太热/太冷 > 其余）→ 逐题问（≤7 题，题型由 agent 定）
      → 每题对要点：清晰 <70% 就追问一次 → 落库（2–3 句）
      → 满 7 题 → 停下，用户选：继续 / 歇 / 停
```

### 第 0 步：先读，再问

两个读操作都免费（无审批）：

```
memory        { action: 'query', track: 'user', scope: 'user-global', limit: 100 }
memory_profile{ action: 'list' }
```

从 `query` 的结果看 `facet` 字段：哪些面有条目、哪些空着。看 `tags`：带 `questionnaire` 的是上次问卷写的。看 `text`：内容是否过时（工具不返回时间戳，「陈旧」靠内容自判——写着「在学 X」而用户已换方向，那就是陈旧）。

`memory_profile` 的 `list` 给出已打分的领域与档位；**没出现的领域就是空白**。

### 第 1 步：挑板块（两端优先）

| 优先级 | 挑谁 | 为什么 |
|---|---|---|
| 最高 | **用户指定** | 他想聊哪块聊哪块 |
| 高 | **太热的**——条目老在变 | 画像最容易过期，值得重新确认 |
| 高 | **太冷的**——长期空白或久未更新 | 覆盖不到位，值得补 |
| 低 | 稳定且还算新的面 | 先放着 |

一句话：**越是两头（老在动 / 老没动），越先问**。一轮最多七题，题目自然落在一两个面上，**不硬卡面数**。

挑完先告诉用户这一轮聊什么（一句话），再开始问。

### 第 2 步：逐题问

题库在 [`references/question-bank.md`](./references/question-bank.md)，按 7 面 × 24 子板块组织，每题标了「要点」。

- **一次只问一题**，等用户答完再问下一题。一口气列一串，那是表格，不是对话。
- **题型由 agent 按题定**：能力、偏好类用选择题（选项 ≤ 4 个，另加「说不准 / 其它」），经历、事实、意愿类用问答题。
- **题目要简单**：问句一行说完，一题只问一件事，不要求用户心算或回忆精确数字。
- **对照要点判含糊**，见下。

### 第 3 步：含糊才追问，70% 是线

每题在题库里标了 **3–4 个要点**（这道题想采到的几个侧面）。答完数一数：

- **答清 ≥ 70%** → 过，不追问。
- **答清 < 70%** → **追问，但只追一次**：把缺的那个侧面换个问法再问一遍。追完不论答没答清，都落库，不纠缠。
- 用户答「不知道 / 不想说 / 跳过」→ 立刻放行，记下这个面没问到，**不绕回来再问**。

**空白好过错值。** 实在问不出的，宁可不写。

一条对照：要点只有 3 个时，70% 实际等于「几乎要答满」；标 4 个要点，70% 才有真正的缓冲。所以题库以 4 要点为主。

### 第 4 步：边答边写

答完一题就写一题（不攒到最后），中途喊停也不丢数据。写入协议见下节。

### 第 5 步：满七题，停下

一轮至多七题。第七题落库后**停下来**，请用户自己选：

- **继续** → 再开一轮（可换面，仍是至多七题）。可以一直答下去，**不设总量上限**。答得越多，画像越厚。
- **先歇** → 就此收尾，下次接着来。
- **到此为止** → 收尾。

停下时给一句话报告：这轮写了哪些面、几条条目、哪些领域打了分；再说下次可以从哪几个面接。**不要复述用户原话，也不要给「人格总结」。**

## 写入协议

### 条目 → `memory` 工具

```
memory {
  action: 'add',
  track: 'user',            // 画像一律 user 轨
  scope: 'user-global',     // 跨工作区
  facet: '<七面之一>',       // 见下方「面 ↔ 板块」表
  tags: ['<板块名>', 'questionnaire'],
  text: '<周级、能力层的一句概括，可 2–3 句>'
}
```

`text` 是**概括条目**：一条一个意思，允许两到三句。别把原话或对话记录搬进去，也别把三件事糊成一条。

```jsonc
// 好
{ "text": "会 Python 与 TypeScript，能独立写中小型工具；Rust 只读得懂，没写过", "facet": "能力与技能", "tags": ["专业能力", "questionnaire"] }
// 坏——原话搬运、无概括
{ "text": "用户说：'我一般吧，写代码还行，不过数学不太行，最近在学 Rust，睡得很晚'" }
```

### 知识水平 → `memory_profile` 工具：抬头半档问

「知识与学科水平」落进结构化的 profile 表，不写成条目充当标尺。

```
memory_profile { action: 'set', domain: '<31 个子领域之一>', level: <1..10> }
```

**问法：拿现有画像当锚，往上抬一点问。** 问题抬到现有档位之上一点，才探得到天花板；问在已知档位处，得不出新东西。

```
档案记 数学 5/10  →  用「6–7 级」的话问一道（能读论文的数学部分吗？）
   接得住   →   上调一档，再试更高一档
   接不住   →   守住当前档
```

每个领域最多试两三次，省题数。**含糊时取低不取高**。

档位尺（`level` 缺省由 `tierForLevel` 推导，一般不传 `tier`）：

| level | 档位 | 含义 |
|---|---|---|
| 1–3 | 科普 | 听得懂科普，不深入 |
| 4–6 | 本科 | 常用概念清楚，能跟上正常讨论（**默认锚点**） |
| 7–8 | 硕士 | 术语自由，能深入细节 |
| 9–10 | 专家 | 行话缩写自由，能讨论边界与不确定 |

`domain` 必须是 31 个子领域之一（`lib/constants.mjs` 的 `KNOWLEDGE_DOMAINS`）。用户只说了几个领域就写几个，**不要为凑满 31 项替他打分**。

### 关于审批

`memory` 的写与 `memory_profile` 的 `set` 都过审批门。审批被拒时，如实告诉用户哪一条没写进去，**不换措辞重试、也不绕过**。

## 口吻

温和体贴，像熟悉他的人。三件事写进话里：

- **退路明说**：「随时可以停」「不想答就跳过」。
- **不评判**：任何答案都不加点语，尤其健康、关系、经济这类敏感的。
- **不做总结**：不替用户下「你是这样的人」的判语。

## 重问：按性子，不按日历

同一个问题**不照原样重问**，也不按固定周期上门。两条一起用：

| 面的性子 | 大概多久回头看一眼 |
|---|---|
| 易变（兴趣、项目、作息、处境、资源） | 一两个月 |
| 中变（技能、习惯、学习方式） | 三个月上下 |
| 慢变（成长经历、三观、身体底子） | 半年到一年，甚至问过就不再问 |

**事件优先于日历**：真值大概变了、或**观察给出矛盾信号**了（例如观察发现作息乱了），才回头问。于是问卷永远「有事才开口」，不按期查户口。重问时换角度、换难度锚点。

## 与观察的边界

问卷问过的面，观察照碰。两边冲突时，**分面裁决**：

| 冲突的面 | 听谁 | 为什么 |
|---|---|---|
| **能力类**（你能做什么） | 听**观察** | 做得到就是做得到 |
| **意愿偏好类**（你想要什么、喜不喜欢） | 听**自陈** | 喜好只有本人说了算 |
| **落差类**（想做却没做） | **两条都留** | 落差本身就是最值钱的画像 |

冲突时**不删、只标注来源与时间**，让模型自己看见落差（例如「意图：想早睡 / 行为：常两点睡」）。

## 面 ↔ 板块对照（写 `facet` 用）

问卷合法的板块共 **24 个**（七面合计 29 个子板块，剔除 5 个仅观察面后为 24；「31」是知识领域数，不是子板块数）。

| facet | 问卷合法子板块 |
|---|---|
| 躯体 | 生理与健康 / 睡眠与饮食节律 / 感官与身体条件 |
| 心智 | 认知能力 / 知识与学科水平（→ `memory_profile`） |
| 价值与意愿 | 三观与信仰 / 道德与伦理立场 / 动机与长期目标 / 兴趣与审美偏好 |
| 能力与技能 | 专业能力 / 通用技能 / 学习能力与学习模式 / 身体技能 |
| 行为与习惯 | 日常作息与生活节律 / 工作与学习习惯 / 协作与交互偏好 |
| 社会与处境 | 社会关系 / 社会身份与角色 / 文化与人际处境 / 资源条件 |
| 经历与轨迹 | 成长与生活经历 / 教育与科研与工作经历 / 项目与作品史 / 成就挫折与转折 |

### 不问的 5 个板块（仅观察，S4 通道）

**思维方式与思辨 · 人格特质 · 情绪模式与心理强度 · 自我认知 · 决策与行动风格**

自陈在这五处最不可靠：人看不见自己的思维盲区、气质与情绪模式，对「我怎么决策」的叙述常与行为相反。它们留给后台观察通道，**不出现在问卷题目里**。

例外：用户**主动**聊到这五处（不是被你问出来的），照常记录，`facet` 照填——主动说的自陈也是数据，只是不作为问卷题目去索取。

## 颗粒度纪律（红线）

问卷问的是**周级、能力层的概括**。以下问法禁止：

| 禁止 | 为什么 | 改成 |
|---|---|---|
| 「你最近一天吃了什么」 | 日流水，明天就过期 | 「你平时吃饭大概怎么解决」 |
| 「你昨天几点睡的」 | 单点事实，噪声 | 「你作息大概什么节奏」 |
| 「矩阵乘法你掌握到什么程度」 | 知识点细节 | 「数学你大概能独立处理到什么层次」 |
| 「你现在在做什么项目，第几周了」 | 项目周报 | 「你手上大致有哪几类项目，做到过什么程度」 |
| 「你觉得自己聪明吗」 | 自评，且属观察面 | 不问 |

落库条目同理：一条概括覆盖一个侧面，用户说了三件事就写三条。

## 一轮示例

```
（读完后）这一轮想聊「能力与技能」和「躯体」，大概 5 个问题，随时可以停。

问：你大概会哪些编程语言，能独立写到哪里？
   A. 基本不会 · B. 会一门，能改别人的脚本 · C. 会两三门，能独立写中小型工具 · D. 多门，能设计并维护较大项目 · 说不准/其它
答：C 吧，Python 和 TS 熟，Rust 只读得懂。
→ memory { action:'add', track:'user', scope:'user-global', facet:'能力与技能',
           tags:['专业能力','questionnaire'],
           text:'会 Python 与 TypeScript，能独立写中小型工具；Rust 只读得懂' }

问：数学上你大概能独立处理到什么层次？
   A. 日常够用 · B. 大学基础（微积分、线代） · C. 能读专业论文的数学部分 · D. 能吃透并自己推
答：B，够用就行。
→ memory_profile { action:'set', domain:'数学', level:5 }

（第七题后）这一轮写了 X 条：……。要继续下一轮，还是先歇会儿？
```
