# 检索加权方案（规格 3.3 「层 B」的零依赖半边 ＋ 向量开关收口）

> **一句话**：把「按需真的捞得回来」做成**排序有据**（相关度 × 热度 × 新旧）＋**匹配面更宽**（正文 ＋ 标签），
> 并把那个会**静默关掉中文召回**的 `retrieval.vector` 开关收口。
> **范围**：零依赖。真语义嵌入（层 B 的另一半）**不在本方案内**——它等「嵌入源」定夺，见 §5。

---

## 0. 结论先行

| 项 | 决定 |
|---|---|
| **载体** | `lib/retrieval.mjs`（加权排序 ＋ 匹配面）＋ `lib/embedding.mjs`（语义声明）＋ `index.mjs`（选路） |
| **依赖** | **零**。不引包、不调模型、不动 schema |
| **排序** | `score = relevance × (1 + 热度权重 × 热度因子) × (1 + 新旧权重 × 新旧因子)`；热度因子带半衰期衰减（断增强回路）；平手退 `relevance` → `rankOrder` |
| **匹配面** | 词元在**正文**命中记满权，只在 **tags** 命中记折权（`tagDiscount`）；无 tags 时行为与今天**逐字不变** |
| **可调** | 六个加权值经 Config `recall.weighting` 下发（DSH 设置页可改、热生效；改后重建检索器） |
| **向量开关** | `retrieval.vector` 只认**声明了语义**的嵌入 provider；伪嵌入不再能让它通过（这是本方案最要紧的一处修复） |
| **可回退** | 集中在三个文件，`git revert` 即回；无 schema 变更、无数据迁移 |

## 1. 现状（勘察结论，逐条看代码）

| 件 | 现状 | 出处 |
|---|---|---|
| 层 A 检索器 | `KeywordRetriever` 默认主路径：CJK 二字 bigram ＋ 拉丁整词 → 命中任一词元即召回 → 相关度 = 0.5×覆盖率 ＋ 0.3×词元长度权重 ＋ 0.2 整串加成 | `lib/retrieval.mjs:88-131` |
| 排序 | `relevance DESC → rankOrder`（`recallCount → updatedAt → id`）——**热度与新旧只是平手时的退路** | `lib/retrieval.mjs:36-42,130` |
| 匹配面 | **只有 `entry.text` 参与匹配**；`tags` / `facet` 不参与 | `lib/retrieval.mjs:113-122` |
| 向量选路 | `buildVectorRetriever()` **写死 `embeddings.get('fake-hash')`** | `index.mjs:2339-2344` |
| 伪嵌入 | `FakeEmbeddingProvider`：按 `[\p{L}\p{N}]+` 切段后哈希分桶 —— **中文整句是一段**，故「偏好」查不到「用户偏好：回复用中文」 | `lib/embedding.mjs:34-52` |
| 契约文档 | `retrieval.vector` 的 README 行写明「（伪嵌入）」，但它挂在「**语义召回开关**」名下 | `README*.md` 配置表 |

**由此得到两处真问题：**

1. **热度与新旧没有进入排序** —— 规格 3.3 改造点③要求的「相关度 × 热度 × 新旧」缺失。库一长大，同样相关的一堆条目里，
   **常用的、新的**不会浮上来，正是「拆上限之后捞不回来」的一半成因。
2. **`retrieval.vector` 是个会静默关掉中文召回的开关** —— 伪嵌入对中文**几乎必零命中**（整句一段、无法子串命中），
   而 `buildVectorRetriever` 恰恰**只认它**。也就是说：主人一旦打开这个名为「语义召回」的开关，
   **中文记忆库的召回会静默塌到接近零**，而且不报错。这正撞本项目最恨的「静默失效」红线。

## 2. 设计

### B-2.1 加权排序（把热度与新旧请进主分）

```
relevance   = min(1, 0.5 × coverage' + 0.3 × weighted' + 0.2 × exactBonus)
heatFactor  = 热度量 × 热度衰减 = min(1, recallCount / HEAT_SATURATION) × 2^(-距上次召回天数 / HEAT_HALF_LIFE_DAYS)
              // 缺 recallCount 或缺 lastRecalled 一律取 0
freshFactor = updatedAt 存在 ? 2^(-ageDays / HALF_LIFE_DAYS) : 1  // 缺 updatedAt 取中性 1，不奖不罚
score       = relevance × (1 + HEAT × heatFactor) × (1 + FRESHNESS × freshFactor)
sort        = score DESC → relevance DESC → rankOrder
```

- 三个现有权重（0.5 / 0.3 / 0.2）**不变**；新增四个常量与两个加成上限，集中成一张表，便于日后调档。
- **缺 `updatedAt` 取加成 0，不是取满额**：首版把「没时间戳」当成中性 1，结果它比「有时间戳但旧」
  还高，把 `rankOrder` 的旧口径整个倒转（本仓测试当场撞出）。改成基线 0 后，缺时间戳 = 不多给也不少给。
- **平手仍退 `rankOrder`**：层 A 的可解释性（召回次数 → 更新 → id）原样保留，只是从「主序」退成「次序」。
- `now` 经 `retrieve(query, entries, { now })` 的**可选第三参**注入（缺省 `Date.now()`）；
  第三方实现忽略它即可，**契约不破**（`retrieve` 仍是二元自洽函数）。

### B-2.2 匹配面扩展（正文 ＋ 标签）

- 词元在 `entry.text` 命中 → 记满权 `1`；只在 `entry.tags`（数组，join 后小写）命中 → 记折权 `tagDiscount`。
- `coverage'` 与 `weighted'` 用加权后的命中量计算；**整串精确加成仍只看正文**（保守）。
- **向后兼容**：`tags` 缺失或为空时，`tagDiscount` 不参与，行为与今天**逐字相同**。

> **一句实话**：「多路召回」在零依赖下能扩的路面**只有这一条**（标签）。真正把「换一种说法也找得到」补上的那条路
> ——语义路——需要真嵌入，即 B-1（§5）。本方案不冒充它。

### B-3 向量开关收口（最要紧的一处）

1. **嵌入 provider 契约加一个可选字段 `semantic?: boolean`**（默认视为 `true`；伪嵌入实现必须显式声明 `false`）。
   `FakeEmbeddingProvider` 声明 `semantic: false`。
2. **`detectVectorBackend` 把「语义」计入可用性**：`available = 有 provider 且 provider.semantic !== false`；
   伪嵌入时给出 `reason: 'embedding provider is not semantic'`。
3. **`buildVectorRetriever` 改走「取第一个语义 provider」**，不再写死 `fake-hash`；没有则返回 `null`（回落 `KeywordRetriever`）。
4. **口径不变的那条守住**：可选后端缺失**不是配置错误**，一律**优雅降级**，不响亮失败（沿用 ARCHITECTURE 既有决策）。
   代价如实记下：`retrieval.vector: true` 而没有真语义 provider 时，它**等于没开**——这是刻意的，比「开了更糟」强。

## 4. 验收

1. **门链 8/8 全绿**（test / lint / typecheck / coverage / readmes / self-contained / artifacts / skill）。
2. **新旧对照**：给一组含「同相关度但召回次数/更新时间不同」的条目，确认新排序把**常用的、新的**浮上来；
   给一组「只在标签里命中」的条目，确认新召回面生效；给一组无 `tags` 的条目，确认排序与旧实现**逐字一致**。
3. **开关收口**：`retrieval.vector: true` 且只有伪嵌入 → 装不上 vector、回落 keyword（可断言）；注册一个 `semantic: true` 的
   provider → 装得上（单测层可断言）。

## 5. 明确不做（层 B 的另一半）

- **不接真语义嵌入**：本机 DSH 里没有可用的嵌入端点（`settings.yaml` 的 `llm-deepseek` 只有对话模型），
  本地模型又破零依赖红线。**卡点是「嵌入源」这个决定，不是工程量**——等主人定夺后另开一轮。
- 不引外部包、不建 ANN 索引、不动 store schema、不改 `SubstringRetriever` 与 `VectorRetriever` 的既有行为。
