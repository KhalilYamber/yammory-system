# F5 · 会话级记忆开关方案

> **目标**：每个会话一个开关——关掉 = **注入停、召回禁、写入停、观察不碰**（后两条同源于规格 3.6）。
> **范围**：状态存储（schema v6）＋ 拦截链（协议层 ＋ 工具层）＋ 命令面 ＋ composer 开关。
> **一句话**：把「这个会话，我不留痕」做成一条**不可绕过**的硬语义，而不是一句口号。
> **上游契约**：`docs/记忆机制v2规格.md` 3.4（开关本体）与 3.6（与观察通道的关系，用户已拍板「不碰」）。

---

## 0. 结论先行

| 项 | 决定 |
|---|---|
| **状态存哪** | 插件自有 SQLite，新表 `session_switch(session_id PK, enabled, updated_at)`；**schema v5 → v6** |
| **默认值** | **默认开**（无行的会话视作开启）；只保留「关」的行，重开即删行 |
| **写入拦截点** | `lib/protocol.mjs` 的 `MemoryProtocolCore` 写方法**内部**（同审批门的位置），任何路径绕不过 |
| **读／工具拦截点** | `index.mjs`：预热段 `text` 回调、`memory_recall`、`memory_observe.scan` |
| **关掉后已注入怎么办** | **开关优先于会话内冻结**：关掉后清该会话的冻结缓存，下次 assemble 返回空段（注入立刻停） |
| **管理面** | `/memory list · query · budgets · audit · adapters · export · proposals` 等**只读**子命令**不受影响**；`import` / 提案 approve 属写，受影响 |
| **命令** | `/memory session [on｜off｜status]`（无参 = status） |
| **UI** | `conversation.composer.dock` 注册一个开关钮（session scope，组件从 props 拿 sessionId） |
| **新增配置** | **不新增 Config 项**（守「策略集中、不做开关」纪律） |
| **新错误码** | `SESSION_MEMORY_OFF` |
| **红线** | 开关状态**绝不写会话日志**（`memory/*` 事件未注册，写入会让该会话下次加载被拒）；审计行**只记动作与 outcome，text 恒为 null** |

**替用户先定的三处**（可推翻）：① 默认开；② 关掉立刻停注入（不清历史轮次里已进的文本）；③ 一次做全（命令 ＋ 拦截 ＋ UI），不留半成品。

## 2. 设计

### 2.1 状态模型（schema v6）

```sql
CREATE TABLE IF NOT EXISTS session_switch (
  session_id TEXT PRIMARY KEY,
  enabled    INTEGER NOT NULL,   -- 0 = 关，1 = 开（当前只写 0 行；1 由删除表达）
  updated_at INTEGER NOT NULL
);
```

- 迁移：`if (current < 6) { db.exec(SESSION_SWITCH_SCHEMA_SQL); current = 6 }`；常量 `SCHEMA_VERSION = 6`。
- **存储 API**（`lib/store.mjs`，挂在 store 句柄上，与 `profileList/profileSet` 同级）：
  - `sessionEnabled(sessionId)` → `boolean`（无行、空 id、非字符串 → `true`）
  - `sessionSetEnabled(sessionId, enabled)` → `boolean`（enabled=false 写 0 行 upsert；true 删行；返回落库后的值）
  - `disabledSessionIds()` → `string[]`（全部 enabled=0 的 session_id，供观察排除用）

### 2.2 拦截链（五处，一处都不能漏）

| # | 位置 | 行为 | 备注 |
|---|---|---|---|
| 1 | `MemoryProtocolCore` 写方法（add / replace / remove / consolidate / seed / setProfile）开头 | 取 `write.agent.session.id`；`sessionEnabled === false` → 抛 `SessionMemoryOffError`（在预算预检与 gate **之前**）；落一条 `write` 审计行，`outcome='session-off'`、`text=null`、`session_id` 照记 | 「不可绕过」的落点与审批门同级 |
| 2 | 预热段 `text` 回调（`index.mjs`） | `sessionEnabled === false` → **删冻结缓存** ＋ 返回 `''`（不注入、不落 `snapshot` 审计） | 开关优先于冻结；已进历史轮次的文本不追溯清除 |
| 3 | `memory_recall` execute | 关 → `{ok:false, error:{code:'SESSION_MEMORY_OFF'}}`，不检索、不 `bumpRecall`、不落 `recalled` 审计 | 模型面「召回禁」 |
| 4 | `memory_observe.scan`（`scanObservationHistory` 入口） | 当前会话关闭 → 抛 `SessionMemoryOffError`（工具层转 `ok:false`） | 「关了记忆的会话，观察也不碰」的当下半边 |
| 5 | `scanObservationHistory` 选区 | `filterSessions` 结果**先滤掉 `disabledSessionIds()` 命中的会话**，再截断；被滤掉的条数计入账单（`scanned.skippedOff`） | 规格 3.6 的历史半边 |

补充口径：

- **`memory` 工具的 `query` 动作**：属会话内读，但它是「模型按需查库」而非「按需召回」。判定为**与 `memory_recall` 同档：关则拒**（模型面读记忆一律停）。用户的管理命令 `/memory list|query` **不受影响**（管理面）。
- **`memory_profile` 的 `list`/`get`**：只读管理，不受影响；`set` 属写，受（经协议层拦截）。
- **`memory_observe` 的 `commit`**：走 `service.seed`，已被 #1 覆盖，工具层不必重复拦截（但可在工具层前置一次，给更早、更清楚的报错，二者不冲突）。
- **工具层与协议层重复拦截**的结果一致性：以协议层为准（工具层早报是体验优化，协议层是安全保证）。

### 2.3 命令面

```
/memory session            → status：当前会话 ID（短码）＋ 开关状态 ＋ 切换提示
/memory session on|off     → 切换，落 audit(action='session-switch', outcome='on'|'off')
```

- 需要 `invocation.agent.session.id`；拿不到 → 报错（命令总在会话内执行，拿不到即异常）。
- 文案（en/zh）进 `lib/strings.mjs` 的 `COMMAND_TEXT`；`/memory` 帮助文本（usage）补一行。
- 不新增 Config、不加 `ask` 审批（开关是用户自己的控制，且命令本身就是用户动作；UI 路径同理）。

### 2.4 composer 开关（UI）

- 注册到 **`conversation.composer.dock`**（`kind: 'list'`, `scope: 'session'`），参考件：`packages/client/ui-chat/src/client/apply.ts:165` 的 stats 注册；插件内参考件：`client/client.js:817` 的 `settings.section` 注册。
- 组件通过 session scope 注入的 standard props 取 `sessionId`；语言经 `/api/memento/session` 响应的 `language` 字段下发（与面板同口径）。
- **路由**（走 `ctx.connection.fetch.register`，与既有面板路由同一条栅栏）：
  - `GET  /api/memento/session?sessionId=<id>` → `{sessionId, enabled, language}`
  - `POST /api/memento/session` body `{sessionId, enabled}` → `{sessionId, enabled, language}`（**只允许切换开关**，不接受任何其它字段；sessionId 必须为非空字符串且 ≤ 200 字符，否则 400）
- 视觉：开启态与关闭态各一个文案（🧠 开 / 划掉或灰态），点击即 POST 并就地刷新。
- **不接受审批**：与「面板只读」决策（架构决策 9）不冲突——面板只读指「不改**记忆内容**」；会话开关是用户对本会话的控制件，不是记忆写操作。

### 2.5 常量 / 错误 / 审计

| 项 | 内容 |
|---|---|
| `SCHEMA_VERSION` | 5 → **6** |
| 新常量 | `SESSION_SWITCH_SCHEMA_SQL`（store 内）；`SESSION_DEFAULT_ENABLED = true`（constants，语义锚点） |
| 新错误码 | `ERROR_CODES.SESSION_MEMORY_OFF = 'SESSION_MEMORY_OFF'` |
| 新错误类 | `SessionMemoryOffError`（`lib/errors.mjs`，形状照 `WriteDeniedError` 同级） |
| 新审计动作 | `session-switch`（切换），`outcome='on'|'off'`，`text=null`；写拒绝：`outcome='session-off'`，`text=null` |

## 5. 验收

1. 门链 8/8 全绿，测试数 ≥ 263 ＋ 新增。
2. **端到端手验**（真机 Web profile）：`/memory session off` 后，同会话再开一轮 → 预热段为空；`memory_recall` 返回 `SESSION_MEMORY_OFF`；`memory` 工具写被拒；`/memory session on` 后恢复。

4. 审计里 `session-switch` 行存在且 `text` 为空。

## 6. 明确不做（本期边界）

- 不做「按工作区／按 agent 的开关」（只做会话级）。
- 不做「关闭后追溯清除已进历史轮次的注入文本」。
- 不做开关的 Config 项、不做审批流（用户动作，非模型写）。
- 不碰 F6（整理机）与 F7（可观测三数）——它们是下一站。
- UI 若与宿主 slot 契约冲突（注册被拒／props 拿不到 sessionId），**先保全 1–6 步（命令面 ＋ 拦截链），UI 降级为只读状态显示并在交付报告里如实登记**，不得为凑 UI 而改宿主或绕过栅栏。
