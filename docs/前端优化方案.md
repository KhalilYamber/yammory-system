# 前端优化方案（client.js：对齐官方，去自造）

> **目标**：把 `client/client.js` 的自造控件与自造样式，换成 DSH 官方已提供的原语与设计令牌；功能一字不变。
> **纪律（ponytail）**：零构建不变、插槽注册不变、逻辑不变；只换「控件来源」与「颜色来源」。

---

## 0. 结论先行

| 项 | 决定 |
|---|---|
| **技术前提（已核实）** | 宿主给插件开放的**平台种子模块**里，**就有** `react` / `react-dom/client` / `@deepseek-ai/dsh-client-ui-primitives` / `ui-slots` / `ui-store` —— **零构建可直接 `require`**（源码：`packages/client/web/src/seed.ts`） |
| **修正一处原计划** | 官方原语**是 React 组件**，所以「换控件」必然要求「用 React 渲染」——原来说的「第一步换控件、第二步迁 React」**耦合了**。改为：**第一步纯样式对齐；第二步迁 React ＋ 换控件**（合并） |
| **现状盘点** | 插槽注册（`composer.dock` 开关钮 / `settings.section` 设置页）**已经是 React 组件**（用了 `react.createElement`）；**只有抽屉面板**是手搓 DOM |
| **第一步范围** | 样式：硬编码色值 → 官方 `--dsw-alias-*` 令牌；核对 token 名；去掉不必要的 fallback |
| **第二步范围** | ① 开关钮换官方 `Switch`/`Pill`；② 抽屉从 `document.createElement` 迁到 React（`createRoot`）；③ 抽屉内控件换官方 `Button`/`Input`/`Tag`/`Pill`/`Modal`/`Tooltip`；④（可选）抽屉改走官方 slot |
| **不动** | 零构建（不引打包器）、插槽注册方式、面板数据面（`/api/memento/*`）、`placeOpenButton` 的让位逻辑 |

## 1. 已核实的技术前提

宿主在浏览器侧维护一张**平台单例种子表**（`getStaticModules()`），插件 `require` 时可命中：

```
react · react/jsx-runtime · react-dom · react-dom/client
@deepseek-ai/cordis
@deepseek-ai/dsh-client-store
@deepseek-ai/dsh-client-ui-slots
@deepseek-ai/dsh-client-ui-primitives      ← 官方控件库
@deepseek-ai/dsh-client-ui-dockkit
```

解析规则（`client/modules/src/client/system.ts`）：`require(spec)` 依次查 **种子表 → 已物化模块 → 已注册的包工厂**；三者皆不中即**响亮抛错**。所以只要用上面的 specifier，**零构建包也能直接拿到官方控件**。

`ui-primitives` 的纪律（其 README）：**「插件无法 import 另一个插件的组件，因此本包是控件唯一可以共享的地方：合适的就复用，有意的视觉差异提升成 prop，而不是另起一份拷贝。」**

## 2. 第一步：样式对齐令牌

### 2.1 现状

- 代码里已有正确用法：`var(--dsw-alias-label-secondary, #8a93a6)`、`var(--dsw-alias-label-tertiary, #98a2b3)`
- 但也存在**硬编码色值**：`#3f6fae`、`#1c2a42`、`#cfe1f7`、`#2f4466`、`#9fb4d4`、`#ff…` 等

### 2.2 做什么

1. 逐条把**硬编码色**映射到官方 `--dsw-alias-*` / `--dsw-static-*` 令牌（对照 `packages/client/ui-theme/src/styles/design-platform.css`）；
2. 核对现有 `--dsw-*` 变量名是否真实存在（不存在的改名或换等价 token）；
3. **去掉不必要的 fallback**（保留亦可，但须与官方语义一致；怀疑 token 不存在时才留）；
4. 结果：**亮/暗主题自动跟随**（这些 token 由官方主题层按明暗重设）。

---

## 3. 第二步：迁 React ＋ 换官方控件

### 3.1 开关钮（插槽组件，已是 React）

- 现在：自造 `button.memswitch` + `.memswitch-dot`
- 换成：官方 `Switch`（36×20 双态开关，`label` 必填）或 `Pill`（可选中胶囊）
  - 选型判据：单一开关语义 → `Switch`；若需与其它 chip 并排的轻量观感 → `Pill`
  - **首选 `Switch`**（语义最正），若与 composer dock 的排布冲突再退到 `Pill`

### 3.2 抽屉面板（手搓 DOM → React）

- 现在：`installPanel()` 里 `document.createElement('style') + 容器 + innerHTML`，事件用 `addEventListener`
- 改成：`require('react-dom/client')` 的 `createRoot` 挂到自建容器，组件用 `react.createElement`（无 JSX，零构建）
- **结构照搬**：条目浏览 / 搜索框 / 预算条 / 审计尾 / 提案区 / 三数行，位置与文案不变
- **控件换代**：
  | 现在 | 换成 |
  |---|---|
  | 搜索输入框 | `Input` |
  | 「刷新」「关闭」等按钮 | `Button`（`variant: 'ghost'` / `'toolbar'`） |
  | 分组计数、状态点 | `Tag` / `Pill` / `StateDot` |
  | 浮动容器（若要 modal 化） | `Modal`（**不强制**，保持悬浮抽屉亦可） |
  | 悬停提示 | `Tooltip` |
- **列表渲染**：用 React 的 key 渲染，不再手拼 `innerHTML`；`escapeHtml` 随之删除（React 默认转义）

### 3.3 可选：抽屉改走官方 slot

- 现状自建 fixed 层 + `MutationObserver` 追踪 tidewatch 徽章让位（**唯一一对插件间硬耦合**）
- 参照 `dsh-tidewatch`：它把浮动组件挂在 **root 级 `shell.overlay`** 插槽
- **先查** DSH 是否有合适的 root 级浮层 slot；有则迁过去（**顺带解耦**），没有则保持自建层

## 4. 施工分解

| 步 | 文件 | 做什么 |
|---|---|---|
| 1 | `client/client.js` | **第一步**：色值/token 对齐（纯样式，不改结构） |
| 2 | `client/client.js` | 开关钮换 `Switch`/`Pill`（插槽部分，低风险） |
| 3 | `client/client.js` | 抽屉迁 React（`createRoot` ＋ 组件化；结构、文案、行为照旧） |
| 4 | `client/client.js` | 抽屉内控件换官方原语；删自造 CSS 与 `escapeHtml` |
| 5 | （可选）`client/client.js` | 抽屉迁官方 slot（若查得可用） |
| 6 | 文档 | `CHANGELOG.md`、`ARCHITECTURE.md`（面板/client 口径）、`AGENTS.md` 模块表若涉及 |

## 5. 验收

1. **功能一字不变**：面板（条目/搜索/预算/审计/提案/三数）、开关钮、设置页行为与位置照旧；
2. **视觉对齐**：控件观感与官方一致；**亮/暗主题切换跟随**；
3. **门链 8/8 全绿**（含 `lint` / `typecheck` / 五语）；
4. **零构建不变**：package.json 的 `exports["./client"]` 仍指向手写 `client.js`，无新增构建步骤；
5. **可回退**：改动集中在 `client/client.js` 一个文件，`git revert` 即回。

---

## 6. 边界与风险

- **不引入打包器**（JSX 不给用，一律 `react.createElement`）——与 tidewatch 同款做法；
- **UI 观感无法自动验证**：DSH 写的代码只能保证结构与逻辑，**视觉终验须由人在浏览器里看**；
- `ui-primitives` 若在某处 props 不合用，**提成 prop / 用本地变体**，别复制它的实现；
- 不碰面板数据面（`/api/memento/*`）与后端。

## 8. 第二轮（0915）·设置卡片

上一节修的是抽屉；这一轮只动**宿主设置页那张卡片**（`CARD_STRINGS` / `FIELD_GROUPS` / `CARD_CSS` / `FieldRow` / `YammorySection`）。症状是同一张设置页里两套语言：本卡片还在手搓原生 `<input type=checkbox>`、原生 `<select>` 与自造边框按钮。

| # | 症状 | 修法 |
|---|---|---|
| 1 | 控件不是一套：checkbox / select / 自造按钮 | 换成官方原语：`Switch`（字段名当 `label`）、`Input`、`Pill` 组（`active` 标当前值，点一下即改）、`Button`（reset / discard / save，**保存是唯一的 `primary`**） |
| 2 | 27 个字段各压一条 `border-top`，拉成一道长梯子 | `.memcard-field` 去掉 `border-top`，只留 `padding: 9px 0` 与 `gap: 2px` |
| 3 | 分组标题（12px/600 灰）与字段标签（13px）几乎同级 | 降为眉标：11px / tertiary / 字距 0.03em，并在组间加一条 `border-top` 分隔线 |
| 4 | 标签右侧挤着 `⟳` 徽标、`· 已覆盖`、`重置` 三件形态各异的小东西 | 统一成官方原子：`Tag`（`neutral` = 状态事实「已覆盖」；`quiet` = 提示「⟳」）＋ `Button`（ghost/sm 的重置）；`⟳` 的说明走官方 `Tooltip`（不给 `Tag` 传 `title`） |
| 5 | 动作栏压在字段区**上方**，滚到底还得滚回去按保存 | 整块下移到字段区之后，类名改 `.memsec-actions`（`border-top` 收尾），脏标记与失败提示留在同一行左侧 |
| 6 | `retrieval.vector` 挂在「召回默认值」组里，位置不对且无说明 | 独立成组 `sectionRetrieval`，并补 `hintRetrievalVector`：「只有注册了声明为语义的 embedding provider 时才真正生效；内置是哈希伪嵌入，打开也回落 keyword」 |

配套的两张映射表把原先写死的分支收成数据：`CHOICE_LABELS`（选择型候选 → 文案键，缺键回落原始值）与 `FIELD_HINTS`（路径 → 说明文案键，原先 WritePolicies / dbPath 的两条三元分支改成查表）。

**数据逻辑一字未动**：`CardForm` / `parseDraftText` / `pathValue` / `pathStored` / `deepMerge` / `FIELD_SPECS` 的 kind 与 path、保存与校验流程全部原样；这轮只换「控件来源」与「样式」。

**测试覆盖为零（如实登记）**：设置卡片在测试桩（`test/client-harness.mjs`）里不渲染 —— 桩只覆盖抽屉与会话开关，`settingsScope` 是只读快照，`state.available === false` 时字段区整块不渲染。因此自动化只能保证两件事：代码可加载（`npm test` 的既有用例会 import 整个 `client.js`）与两块自造样式不含硬编码色值 / `rgba(`（正则断言跑在 `PANEL_LAYOUT_CSS` 与 `CARD_CSS` 的合体上）。**间距、控件宽度、Pill 组的观感须人在设置页里终验**；本轮没有为「让卡片可测」新增或修改任何测试文件。

## 9. 第三轮（0915）·设置项说明

上一轮把卡片对齐了官方原语；这一轮只加一件东西：**每个设置项标签旁一枚圆圈问号，点一下在字段下方展开一张小卡片，用大白话讲这一项是做什么的。** 起因是那张卡片有 30 个字段，标签写着 `热度半衰期（天）`、`仅标签命中的折扣` 这类短语，默认读者已经知道这个旋钮在管什么。

| 面 | 落点 |
|---|---|
| 图标 | 官方 `IconQuestionOutline14`（圆圈套问号，14px，`fill="currentColor"`），经 `getPrimitives()` 取；**不自造 SVG、不引第二枚图标**。已核实导出链：包 `src/index.ts` 末行 `export * from './icons/index.tsx'`，且构建产物 `lib/index.js` 里确有该符号 |
| 按钮 | 官方 `Button`，`variant: 'ghost'` / `size: 'sm'`，`icon` 传图标；无障碍名走 `CARD_STRINGS` 新增的 `helpLabel`（en「What this setting does」／zh「这一项是做什么的」），不显示在界面上 |
| 位置 | 标签文字**之后、`FieldBadges` 之前**（`FieldRow` 的 `<label>` 内部）；`note === null` 时不渲染，所以没有说明的字段不会出现假问号 |
| 交互 | 点一下展开、再点一下收起，`aria-expanded` 跟着开关走；`onClick` 里 `event.preventDefault()` ＋ `event.stopPropagation()`，因为按钮在 `<label>` 里，不挡就会把焦点交给输入控件 |
| 说明卡 | 挂在字段最下方（`hint` 与 `invalid` 之后）的 `.memcard-note`，底色 `--dsw-alias-bg-module-platform`，12px / 行高 1.7 |
| 样式 | `CARD_CSS` 新增三条：`.memcard-help`（22px 圆、`padding: 0`、`margin-left: 6px`、tertiary）、`:hover:not(:disabled)`（转 primary）、`.memcard-note`。**颜色一律走令牌，无硬编码色值、无 `rgba(`** |

**文案来源**：新增 `FIELD_NOTES`（Map，路径 → `{ en, zh }`），放在 `CHOICE_LABELS` / `FIELD_HINTS` 同一带，与 `FIELD_SPECS` 紧邻。两种语言相邻、一项一段，便于对照维护；取值用 `noteFor(path, language)`，缺省英文、缺项返回 `null`。本轮 30 条覆盖 `FIELD_SPECS` 的全部 30 个路径，经脚本逐字节比对（7,655 字符一致）并核对键集合：无缺项、无多余键、无重复键。

**数据逻辑一字未动**：控件分支（`Switch` / `Pill` 组 / `textarea` / `Input`）、`FIELD_SPECS`、`CardForm`、`parseDraftText`、保存与校验流程全部原样；本轮只加「一行说明」与「三条样式」。

**测试覆盖同样为零（如实登记）**：设置卡片在测试桩（`test/client-harness.mjs`）里不渲染 —— 桩只覆盖抽屉与会话开关，`settingsScope` 是只读快照，`state.available === false` 时字段区整块不渲染，所以 `FieldRow` 里新增的 `useState` 与问号按钮在测试里一行都不会执行。自动化能保证的仍只有两件：代码可加载（既有用例 import 整个 `client.js`）与两块自造样式不含硬编码色值 / `rgba(`。**问号按钮的观感、与标签的垂直对齐、点开之后说明卡的排版，须人在设置页里终验**；本轮没有为「让问号可测」新增或修改任何测试文件。

## 10. 第四轮（0915）·入口迁侧栏

本轮只做一件事：把面板入口从「右下角悬浮按钮」搬进官方侧栏槽位 `sidebar.footer.action`，与「设置」同处侧栏脚区。动机是物理重叠——原来那枚按钮钉在 `position: fixed; right: 16px; bottom: 56px`，正好压在 dsh-tidewatch 峰谷卡片入口上，两者争同一块地方、互相挡字。搬进槽位后，脚区排布归宿主管，两个插件不再争同一块像素。

| 面 | 落点 |
|---|---|
| 槽位 | `sidebar.footer.action`。`packages/client/ui-sidebar` 声明为 `{ kind: 'list', scope: 'root', owner: SidebarFooterActionOwnerProps }`，owner props 只有一个 `{ wide: boolean }`；`SidebarRoot.tsx` 把它渲染在 `sidebar.settings` **之上**的 `footArea` 里，两栏宽都渲染 |
| 同槽位占用者 | ui-cordis 的 `CordisPanel`（`packages/extensions/ui-cordis`）。本轮几何的出处就是它的 `.badge` |
| 注册 | `ctx.effect(() => ctx.slots.inject('sidebar.footer.action', () => ctx.slots.register({ name, id: 'yammory-system-entry', order: 20 }, MemoryEntryButton)))`；落座与否由**工厂是否真的跑起来**判定，没落座就回落悬浮按钮（见下方第 3 条） |
| 图标 | 官方 `IconDatabaseOutline16`（已核实：`ui-primitives/src/icons/index.tsx` 导出，该文件经包 `src/index.ts` 末行 `export * from './icons/index.tsx'` 上到包面）。不自造 SVG |
| 几何 | 照抄 `.badge`：`height: 42px` / `border-radius: 12px` / `padding: 0 10px 0 8px` / 透明底 / hover 走 `--dsw-alias-interactive-bg-hover`。**同一槽位里两枚动作必须长得同族**，尺寸自创的话人眼一眼就看出破绽 |
| 宽窄 | `wide === false`（56px 窄栏）只出图标，宽栏出「图标 ＋ 文字」。判定用槽位递进来的 `wide`，不自己量宽度 |
| 降级 | 槽位一直没声明、或注册同步抛错时，不静默丢入口：`floatingSeat` 置位，`bootPanel` 挂回原来的右下角悬浮按钮（`PanelButton` 与 `#mem-open` 的规则都保留） |

**四处与规格字面的偏离，都是在代码现状上撞出来的，逐条记账**：

1. **入口类名 `.mem-entry` → `.mem-side-entry`（id 仍是 `mem-entry`）。** 抽屉条目行早就占着 `.mem-entry`（`client.js` 里 `.mem-entry { padding: 7px 0; border-bottom: … }` 与其 `:last-child` / `.t` / `.m` 三条衍生规则）。规格给的新规则是**同权重、后写**，浏览器里后者赢，于是「42px 高、无下划线分隔、`overflow: hidden`」会整套盖到抽屉的记忆行上，把条目列表压成一条条无分隔的窄条——这正是本轮红线里「抽屉本体一律不动」要防的那种改坏。改名后两条规则互不相干，注释也写在了 CSS 里。
2. **主路径也要跑一次 `bootPanel`（探测），另设 `floatingSeat` 当闸。** 规格把 `bootPanel` 只留给降级路径，但 `entryLanguage` 是侧栏入口文案的唯一来源：主路径若从不探测，中文用户在侧栏里会一直看到 `Memory`（抽屉侧的语言只回写抽屉自己）。所以 `apply` 只保留**一次**探测调用，槽位是否可用改由模块级 `floatingSeat` 表达，`bootPanel` 内部据它决定挂不挂悬浮按钮。同一个闸还堵了设置页那条路：`setPanelButtonVisible(true)` 在 `panelOpenButton === null` 时会去重建悬浮根节点，主路径下若不放这道前置闸，用户一保存设置就会从右下角冒出一枚悬浮按钮，重叠原样回来。顺带把那条分支的 `onToggle` 接回真实出口（规格给的 `() => {}` 会让重新开出来的悬浮按钮点不动抽屉）。
3. **落座判定从「try/catch」改成「工厂是否真的跑起来」。** 规格假定「宿主未声明该槽 → 注册被拒 → 抛错」，官方 `ctx.slots.inject`（`packages/client/ui-renderer/src/client/registry.ts`）的真实语义是：**槽位已声明时同步调回调；未声明时不抛错，只是等着**，等声明落地再调（`register` 才是抛 `slot "X" is not declared` 的那一层）。照字面写会得到反效果——老宿主上工厂永不运行、`entryInSlot` 却被置成 `true`，于是侧栏没有入口、悬浮按钮又永不回落，入口整条静默消失。现在 `entryInSlot` 由工厂自己置位（跑起来才算落座），try/catch 留着接「注册同步抛错」那一类；槽位若**后来**才声明，工厂跑起来时会调 `retireFloatingSeat()` 把已挂上的悬浮入口就地退役（`floatingSeat` 关掉 + 旧根节点隐藏），不会出现两枚入口并存。
4. **测试里 `slots.registered[1]` 的断言改成按名字找。** 侧栏入口插在浮层之前，槽位账本的下标整体后移一位，原来那两条 `registered[1]` 断言会指向入口而不是 `shell.overlay`。改成 `find(o => o.name === 'shell.overlay')`，下次挪序不会再断在这里。

顺带的三处口径同步：`STRINGS[en|zh].open` 去掉 🧠（图形交给官方图标，文字只留标签），`CARD_STRINGS.panelEnabled` 改成「显示侧栏的记忆入口」，`FIELD_NOTES` 的 `panel.enabled` 一条整条重写（其余 29 条逐字未动）。

**主路径的样式来源也换了一处（不改观感，只改装载时机）**：入口不再住在面板根节点里，`installPanelStyles()` 原先只在 `installPanel` 里调用，而主路径根本不跑 `installPanel`——抽屉定位与侧栏入口几何都会整套缺失（抽屉会塌成一摊正文铺在界面上）。现在这份 chrome 样式表在 `apply` 里装，`installPanel` 里那次保留给降级路径，幂等。

**测试桩新增一个显式 `renderSlot` 帮手（本轮唯一被允许的 test 改动）**：桩此前的口径是「槽位组件一律不渲染」，而侧栏入口正是一枚槽位组件，不渲染就断言不到。新帮手只在测试里显式调用、绝不自动渲染任何槽位。**设置卡片仍保持不渲染，其自动化覆盖依旧为零**——`settingsScope` 是只读快照，`state.available === false` 时字段区整块不渲染，本轮给桩加的口子没有改变这一点。自动化现在能钉住的是：注入顺序与槽位注册（①）、CSS 无硬编码色值 / `rgba(`（②）、入口文字与「点一下开抽屉」（③④⑤）。

**降级路径同样零自动化覆盖（如实登记）**：桩里的 `slots.inject` 永远成功，`floatingSeat` 恒为 `false`，因此 `installPanel` / `PanelButton` / `retireFloatingSeat` 在测试里一行都不执行。要覆盖它得让桩支持「拒绝指定槽位」——那是 test 侧的第四项改动，超出了本轮「唯一被允许的三项」的边界，故只登记、不动手。这一段的正确性目前靠人眼：把插件装进一个没有 `sidebar.footer.action` 的宿主，看右下角是否照旧浮现入口。

**窄栏（56px）与间距未验**：`wide === false` 时只出图标，走的仍是同一套 `width: 100%` 几何；官方占用者 `CordisPanel` 在窄栏另有一套 `.rail` 规则（36×36 圆、`justify-content: center`），本插件没有这一套。图标是否居中、与「设置」和 W 的间距是否舒服，**须人在浏览器里终验**。

**遗留口径债（本轮红线限定了改动文件集，故只登记、未动）**：五语 README 与 `ARCHITECTURE.md` 仍写着「floating panel button / 悬浮窗按钮」，`CARD_STRINGS.sectionPanel`（en「Floating panel」/ zh「悬浮窗」）也还是旧口径；`panel.enabled` 的实际语义本轮已经变成「侧栏入口的显隐」，这四处宜下一轮一起收。
