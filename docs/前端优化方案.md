# 前端优化方案（client.js：对齐官方，去自造）

> **目标**：把 `client/client.js` 的自造控件与自造样式，换成 DSH 官方已提供的原语与设计令牌；功能一字不变。
> **纪律（ponytail）**：零构建不变、插槽注册不变、逻辑不变；只换「控件来源」与「颜色来源」。

---

## 0. 结论先行

| 项 | 决定 |
|---|---|
| **技术前提（已核实）** | 宿主给插件开放的**平台种子模块**里，**就有** `react` / `react-dom/client` / `@deepseek-ai/dsh-client-ui-primitives` / `ui-slots` / `ui-store` —— **零构建可直接 `require`**（源码：`packages/client/web/src/seed.ts`） |
| **修正一处原计划** | 官方原语**是 React 组件**，所以「换控件」必然要求「用 React 渲染」——原来说的「第一步换控件、第二步迁 React」**耦合了**。改为：**第一步纯样式对齐；第二步迁 React ＋ 换控件**（合并） |
| **现状盘点** | 插槽注册（`composer.dock` 开关钮 / `settings.section` 设置页）**已经是 React 组件**（用了 `react.createElement`）；**只有抽屉面板**是手搓 DOM |
| **第一步范围** | 样式：硬编码色值 → 官方 `--dsw-alias-*` 令牌；核对 token 名；去掉不必要的 fallback |
| **第二步范围** | ① 开关钮换官方 `Switch`/`Pill`；② 抽屉从 `document.createElement` 迁到 React（`createRoot`）；③ 抽屉内控件换官方 `Button`/`Input`/`Tag`/`Pill`/`Modal`/`Tooltip`；④（可选）抽屉改走官方 slot |
| **不动** | 零构建（不引打包器）、插槽注册方式、面板数据面（`/api/memento/*`）、`placeOpenButton` 的让位逻辑 |

---

## 1. 已核实的技术前提

宿主在浏览器侧维护一张**平台单例种子表**（`getStaticModules()`），插件 `require` 时可命中：

```
react · react/jsx-runtime · react-dom · react-dom/client
@deepseek-ai/cordis
@deepseek-ai/dsh-client-store
@deepseek-ai/dsh-client-ui-slots
@deepseek-ai/dsh-client-ui-primitives      ← 官方控件库
@deepseek-ai/dsh-client-ui-dockkit
```

解析规则（`client/modules/src/client/system.ts`）：`require(spec)` 依次查 **种子表 → 已物化模块 → 已注册的包工厂**；三者皆不中即**响亮抛错**。所以只要用上面的 specifier，**零构建包也能直接拿到官方控件**。

`ui-primitives` 的纪律（其 README）：**「插件无法 import 另一个插件的组件，因此本包是控件唯一可以共享的地方：合适的就复用，有意的视觉差异提升成 prop，而不是另起一份拷贝。」**

## 2. 第一步：样式对齐令牌

### 2.1 现状

- 代码里已有正确用法：`var(--dsw-alias-label-secondary, #8a93a6)`、`var(--dsw-alias-label-tertiary, #98a2b3)`
- 但也存在**硬编码色值**：`#3f6fae`、`#1c2a42`、`#cfe1f7`、`#2f4466`、`#9fb4d4`、`#ff…` 等

### 2.2 做什么

1. 逐条把**硬编码色**映射到官方 `--dsw-alias-*` / `--dsw-static-*` 令牌（对照 `packages/client/ui-theme/src/styles/design-platform.css`）；
2. 核对现有 `--dsw-*` 变量名是否真实存在（不存在的改名或换等价 token）；
3. **去掉不必要的 fallback**（保留亦可，但须与官方语义一致；怀疑 token 不存在时才留）；
4. 结果：**亮/暗主题自动跟随**（这些 token 由官方主题层按明暗重设）。

---

## 3. 第二步：迁 React ＋ 换官方控件

### 3.1 开关钮（插槽组件，已是 React）

- 现在：自造 `button.memswitch` + `.memswitch-dot`
- 换成：官方 `Switch`（36×20 双态开关，`label` 必填）或 `Pill`（可选中胶囊）
  - 选型判据：单一开关语义 → `Switch`；若需与其它 chip 并排的轻量观感 → `Pill`
  - **首选 `Switch`**（语义最正），若与 composer dock 的排布冲突再退到 `Pill`

### 3.2 抽屉面板（手搓 DOM → React）

- 现在：`installPanel()` 里 `document.createElement('style') + 容器 + innerHTML`，事件用 `addEventListener`
- 改成：`require('react-dom/client')` 的 `createRoot` 挂到自建容器，组件用 `react.createElement`（无 JSX，零构建）
- **结构照搬**：条目浏览 / 搜索框 / 预算条 / 审计尾 / 提案区 / 三数行，位置与文案不变
- **控件换代**：
  | 现在 | 换成 |
  |---|---|
  | 搜索输入框 | `Input` |
  | 「刷新」「关闭」等按钮 | `Button`（`variant: 'ghost'` / `'toolbar'`） |
  | 分组计数、状态点 | `Tag` / `Pill` / `StateDot` |
  | 浮动容器（若要 modal 化） | `Modal`（**不强制**，保持悬浮抽屉亦可） |
  | 悬停提示 | `Tooltip` |
- **列表渲染**：用 React 的 key 渲染，不再手拼 `innerHTML`；`escapeHtml` 随之删除（React 默认转义）

### 3.3 可选：抽屉改走官方 slot

- 现状自建 fixed 层 + `MutationObserver` 追踪 tidewatch 徽章让位（**唯一一对插件间硬耦合**）
- 参照 `dsh-tidewatch`：它把浮动组件挂在 **root 级 `shell.overlay`** 插槽
- **先查** DSH 是否有合适的 root 级浮层 slot；有则迁过去（**顺带解耦**），没有则保持自建层

## 4. 施工分解

| 步 | 文件 | 做什么 |
|---|---|---|
| 1 | `client/client.js` | **第一步**：色值/token 对齐（纯样式，不改结构） |
| 2 | `client/client.js` | 开关钮换 `Switch`/`Pill`（插槽部分，低风险） |
| 3 | `client/client.js` | 抽屉迁 React（`createRoot` ＋ 组件化；结构、文案、行为照旧） |
| 4 | `client/client.js` | 抽屉内控件换官方原语；删自造 CSS 与 `escapeHtml` |
| 5 | （可选）`client/client.js` | 抽屉迁官方 slot（若查得可用） |
| 6 | 文档 | `CHANGELOG.md`、`ARCHITECTURE.md`（面板/client 口径）、`AGENTS.md` 模块表若涉及 |

## 5. 验收

1. **功能一字不变**：面板（条目/搜索/预算/审计/提案/三数）、开关钮、设置页行为与位置照旧；
2. **视觉对齐**：控件观感与官方一致；**亮/暗主题切换跟随**；
3. **门链 8/8 全绿**（含 `lint` / `typecheck` / 五语）；
4. **零构建不变**：package.json 的 `exports["./client"]` 仍指向手写 `client.js`，无新增构建步骤；
5. **可回退**：改动集中在 `client/client.js` 一个文件，`git revert` 即回。

---

## 6. 边界与风险

- **不引入打包器**（JSX 不给用，一律 `react.createElement`）——与 tidewatch 同款做法；
- **UI 观感无法自动验证**：DSH 写的代码只能保证结构与逻辑，**视觉终验须由人在浏览器里看**；
- `ui-primitives` 若在某处 props 不合用，**提成 prop / 用本地变体**，别复制它的实现；
- 不碰面板数据面（`/api/memento/*`）与后端。
