# S5 治理方案（soft delete 回滚 ＋ 分面裁决）

> **两件实事**：① soft delete 的**回滚**（`superseded → active`，F6 只做了单向降级）；② 把「分面裁决」从 skill 里的软口径，落成**代码层可执行、可强制、可留痕**的机制。
> **口径来源**：`skills/yammory-survey/SKILL.md`「与观察的边界」表 ＋ `施工清单.md` S3 口径第 6 条——**能力听观察 / 意愿听自陈 / 落差两条都留，不删只标注**。
> **纪律（ponytail）**：复用 F6 的 `supersede` / store / 审计 / 桶内不跨；不新增依赖、定时器、模型通道。

---

## 0. 结论先行

| 项 | 决定 |
|---|---|
| **来源判据** | `source === 'observation'` → 观察；其余（`memory-tool` / `survey` / 第三方）→ 自陈 |
| **面表（裁决表）** | `能力与技能` → 听**观察**；`价值与意愿` → 听**自陈**；其余五面 → **coexist（两条都留）** |
| **裁决方向** | 由表决定「降谁、留谁」，**不接受调用方反向指定**（能力类不许「留自陈、降观察」） |
| **落差** | coexist 的条目**都不降级**，各打 `gap` 标；能力/意愿类里「降级但仍留痕」本身就是落差证据 |
| **留痕** | 降级行审计 `text` 恒为 `null`；每次裁决另落 `audit(action='arbitrate')` |
| **回滚** | 新增 `restore`：只允许 `superseded → active`，走同一审批门与审计 |
| **不做** | 置信门槛（需更多真实观察数据，留 v2）；「是否冲突」的**判定**仍由模型做（语义），本单只把**裁决动作**机制化 |

## 1. soft delete 回滚

| 层 | 做什么 |
|---|---|
| `lib/store.mjs` | `restoreEntries(ids)`：事务内批量 `superseded → active`，返回恢复的条目；未知 id／非 superseded 状态响亮失败 |
| `lib/protocol.mjs` | `restore(input, write)`：`#assertSessionOn` → gate → 事务 → 审计（`action='restore'`） |
| `index.mjs` | `memory` 工具 action 加 `restore`；命令 `/memory restore <id...>` |

回滚只动**会话可见集**（与写定位同语义）。恢复的条目 `version` 不自增（它没被改写）。

## 2. 分面裁决

### 2.1 裁决表（常量，唯一出处）

```js
// lib/constants.mjs
export const ARBITRATION_BY_FACET = {
  能力与技能: 'observation',   // 做得到就是做得到
  价值与意愿: 'self-report',   // 喜好只有本人说了算
  躯体: 'coexist', 心智: 'coexist', 行为与习惯: 'coexist',
  社会与处境: 'coexist', 经历与轨迹: 'coexist',
}
export const GAP_TAG = 'gap'   // 落差标（两块都留时各打一枚）
```

面表**只覆盖七个 facet 值**（`PROFILE_FACETS`）；`facet` 为空/未知 → 响亮拒绝（不猜）。

### 2.2 `arbitrate(input, write)`

```
输入：{ ids }  // 同一桶内、被模型判定为「同一条事实、两个来源」的条目
  1) #assertSessionOn（F5 开关）→ 取条目（会话可见集）→ 桶内不跨校验
  2) 分两组：observation（source==='observation'）／self（其余）
  3) facet 取两组一致的 facet；不一致 → 响亮拒绝
  4) 按 ARBITRATION_BY_FACET[facet]：
     'observation' → 保留 observation 组，降级 self 组
     'self-report' → 保留 self 组，降级 observation 组
     'coexist'     → 都不降级，两组各打 GAP_TAG 标
  5) gate（一次审批，载荷写清「按面裁决：保留 X、降级 Y、理由 Z」）
  6) 一批一事务：降级 ＋ 打标 ＋ 审计（action='arbitrate'）
```

- **从一组里选「保留谁」**：同组多条时，取 `updatedAt` 最新的一条（其余同组条目一并降级）——不给模型挑的机会，规则可复核。
- **方向强制**：表即方向，调用方无反向参数；这样「能力听观察」不是纪律，是代码不变量。
- **与 F6 的关系**：F6 的 `supersede` 管「同一来源的重复合并」；`arbitrate` 管「不同来源的冲突裁决」。两者都走同一审批门与桶内边界。

### 2.3 面

- 工具：`memory` 工具 action 加 `arbitrate`（入参 `ids`）
- 命令：`/memory arbitrate <id...>`
- skill：`skills/yammory-tidy/references/merge-rules.md` 第六节「互相冲突 → 什么都不做」改为「冲突 → 走分面裁决（`arbitrate`）」，并贴上裁决表

## 4. 测试

| 面 | 内容 |
|---|---|
| restore | superseded → active 成功；active 条目 restore 响亮失败；未知 id 失败；批量事务原子 |
| arbitrate · 能力类 | 一组含 observation＋self → 保留 observation、self 被降级；方向不可反 |
| arbitrate · 意愿类 | 反向：保留 self、降级 observation |
| arbitrate · 其余面 | 都不降级，两组各得 `gap` 标 |
| arbitrate · 边界 | 跨桶拒绝；facet 不一致拒绝；facet 为空拒绝；同组多条取最新 |
| 与 F5 联动 | 关灯会话调 restore/arbitrate → 被 `SESSION_MEMORY_OFF` 拦下 |
| 审计 | `arbitrate` 行可查；降级行 `text=null` |
| 回归 | 既有 318 条全绿 |

**门链 8/8**。

## 5. 验收

1. 门链 8/8 全绿。
2. `arbitrate` 在能力类走向与意愿类走向**逐条实测相反**，且都留痕。
3. `restore` 能把降级条目救回，且恢复后重新出现在会话可见集与预热段。

## 6. 边界

- 不新增 Config / 依赖 / 定时器 / 后台模型通道。
- 不引入「置信门槛」（留 v2：需要真实观察数据攒够才定得出线）。
- 「是否冲突」的判定仍由模型做；本单只把**裁决动作**做成不可反的机制。
- 只动会话可见集；跨桶一律拒绝。
